## What we want to improve

Detect changed non-blank lines whose leading-space count differs by exactly one from the nearest unchanged context and from the repository's canonical file baseline; surface each offending hunk as a focused, non-blocking nit.

## Why this matters

Single-space leading-whitespace slips create noisy diffs and inconsistent examples that a maintainer would call out as a cosmetic nit. Targeting the exact one-space deviation keeps comments focused on accidental formatting slips and reduces false positives from intentional re-indentation.

## Examples

- Dockerfile RUN instruction with one extra leading space versus adjacent lines.
- README code block line misaligned by a single leading space compared with nearby lines.

## Keep it focused

- A makefile recipe must begin with a tab character, so reporting a space-count nit would be incorrect.
- A YAML fragment that increases indentation to change nesting level should not be flagged because the extra spaces are syntactically required for the new nesting level meaningfully altering structure rather than being a cosmetic slip .
